# Security findings and release conditions

Confirmed baseline P0 findings: fixed staff credentials, production schema mutation and spreadsheet downloads at startup, permissive CORS, Meta validation bypass outside production, unauthenticated bridge management/webhooks, account fallback, incomplete object checks, forged file content acceptance and optimistic sent statuses.

This iteration adds database-backed authorization/scopes, six roles, hashed one-time employee invitations and password reset, short JWTs with issuer/audience/required claims, per-user token versions, persisted login/webhook rate buckets, bridge authentication/rate limits/loopback binding, strict routing, bounded file content checks and private downloads. Password changes invalidate prior user tokens. Changing grants affects subsequent requests immediately. Authentication and API mutation audit entries omit tokens, passwords, request bodies and document contents. SQL parameter logging and selected legacy PII logs were removed. Mistral context no longer adds stored contact phone/platform IDs; free-text conversation content may still contain personal data, so provider policy/consent remains an open operational requirement.

Production/staging configuration rejects unsafe debug/JWT/origin/bridge/bootstrap values. New JWT claims intentionally require users to sign in again after release. This is an access-token policy, not a complete refresh-session/MFA implementation. File magic/structure checks do not replace antivirus/CDR scanning.

Private student and staff spreadsheets are retained locally but removed from the new Git snapshot and source ZIP. Past Git history can still contain them; history rewriting and retention must be separately approved. Do not publish existing deployment dumps, .env files, Baileys sessions, static uploads or customer documents. Existing published university guides are distinct from private student uploads.

Release conditions: verified isolated migrations/restore, coordinated bridge secrets/network changes, complete negative access tests, explicit assignments/team setup and staging provider checks. Production code/configuration/secrets were not changed. Existing known passwords require controlled reset/invitation issuance by a director; they are not silently reset by migration.

Dependency audit also identified the installed Next.js 16.4.0 as affected by critical advisories GHSA-2464-fhr4-w9xw / GHSA-673q-mjm6-r5xr and high-severity GHSA-p3m5-59mp-jv5r. The maintainers identify 16.4.1 as a fixed release; this branch updates Next.js and eslint-config-next to 16.4.5. See https://nextjs.org/blog/nextjs-security-update-october-14-2026 and the official package advisories. Re-audit and rebuild after dependency updates. Production remains on its prior version until a separately approved release.
